# 왜이슈? (why-trending)

지금 **화제가 된 이슈**가 왜 화제인지를, 확인된 사실만 출처와 함께 30초로 설명해 주는 앱이에요. 안드로이드 앱과 웹 화면이 같은 코드를 써요.

- **컨셉 (2026-10-19 사용자 요청으로 '밈·신조어 중심'에서 바꿨어요)**: 기사·게시글이 갑자기 늘어난 '화제 이슈'를 분야별로 풀어 줘요. 밈·신조어는 8개 분야 중 하나(`meme`)일 뿐이에요. 분야 순서는 경제·세계·연예·스포츠·IT·과학·생활·문화·게임·밈·신조어예요.
- **보여주는 기간은 '고른 분야 수'에 따라 달라져요** (2026-10-19 사용자 요청. 처음엔 "오늘 기준 2일 전까지만"이었다가, 오래된 이슈를 아예 감추지 말고 분야 수에 따라 가변적으로 보여주자는 요청으로 바뀌었어요):
  - 모든 분야를 고르면 오늘·어제·그저께(3일)만 보여줘요.
  - 분야를 적게 고를수록 화면에 보이는 양이 비슷하도록 더 오래전 이슈까지 보여줘요. 분야 수 × 일수가 거의 같게 `일수 = max(3, round(3 × 전체 분야 수 ÷ 고른 분야 수))` 예요(분야가 8개일 때: 7개 3일 · 6개 4일 · 5개 5일 · 4개 6일 · 3개 8일 · 2개 12일).
  - **딱 1개만 고르면 그 분야의 이슈를 모두 보여줘요.**
  - **분야 이름을 누르면 기간과 상관없이 그 분야의 이슈를 지난 것까지 모두 보여줘요** (2026-10-19 사용자 요청: "카테고리를 누르면 과거까지 포함해 전체 내역을 보게"). 오늘 화면의 분야 제목 줄('경제 4개 · 전체 보기 ›')이나 '내 분야' 줄의 분야를 누르면 그 분야의 전체 보기 화면(`#/g/<분야 id>`)이 열려요. 최신 날짜 순으로 20개씩('이슈 더 보기') 펼쳐 보여주고, 뒤로 가면 오늘 화면에서 보던 자리로 돌아와요. 3일보다 오래된 이슈는 지난 이슈 보관함(`archive.json`)에서 받아 오고, 못 받으면 최근 3일 이슈와 '다시 시도' 안내만 보여줘요.
  - 3일이 지난 해설은 해설 화면에 '며칠 전 소식이에요' 안내가 붙어요. 갱신이 며칠 멈춰서 보여줄 기간 안에 이슈가 없으면 '이슈가 아직 없어요' 안내만 보여요(기간 밖의 이슈로 채우지 않아요).
  - 앱은 '오늘'을 **한국 시간**으로 계산해요(기기 시계가 해설의 최신 날짜보다 느리면 해설의 최신 날짜를 오늘로 봐요).
- 하단 탭은 **오늘**(내 분야별 이슈. 기간은 위 규칙. 분야 이름을 누르면 그 분야 전체 보기) · **검색**(분야로 걸러 보거나 글자로 찾기. 예전 '사전' 탭이 바뀐 것. 아무것도 안 치고 '전체'면 최근 3일, 분야 하나를 누르면 그 분야 전부, **글자를 치면 보관함의 지난 이슈까지 모두** 찾아요) · **알림**이에요.
- **사실만 담담하게**: 시위·파업, 증시·환율·유가의 큰 변동, 금리·물가 발표, 법·제도 시행, 국회·정부가 이미 내린 결정('정책' 카드) 같은 이슈도 다루지만, 기사에 나온 사실과 누가 밝혔는지만 써요. 평가·추측·전망·투자 권유·자극적인 표현은 쓰지 않고(검사가 일부를 막아요), 정당·정치인 공방, 선거, 범죄·사건사고·재난·사망, 전쟁·테러, 확인되지 않은 의혹은 계속 다루지 않아요.

> 해설은 AI가 여러 출처를 확인해 정리한 요약이에요. 틀릴 수 있어서 모든 해설에 출처 링크를 달고, 앱 안에 '내용이 이상해요' 신고 버튼을 두었어요.

## 폴더

| 폴더 | 내용 |
| --- | --- |
| `site/` | 화면(HTML·CSS·JS)과 매일 바뀌는 해설 데이터(`site/data/`). GitHub Pages로 올라가요. |
| `app/` | 안드로이드 앱 껍데기(Capacitor) 설정. 빌드할 때 `site/`를 복사해 넣어요. |
| `scripts/` | 해설 데이터 검사·합치기 도구(`content.mjs`), 아침 알림 보내기(`push.mjs`), 아이콘 생성기 등 |
| `.github/workflows/` | 자동 빌드(`android.yml`), 사이트 배포(`pages.yml`), 아침 알림 보내기(`push.yml`) |
| `ops/` | 매일 해설을 갱신하는 담당이 읽는 지침(`daily-job.md`, `fallback-runner.md`). 사이트·앱에는 올라가지 않아요. |

## 해설 데이터 규칙

- 모든 카드는 **서로 다른 매체 2곳 이상**의 출처가 있어야 해요.
- **오늘 화제인 것을 오늘 기사로**: 카드 날짜 기준으로 가장 최근 출처가 1일 이내(밈·신조어는 3일), 3일 이내 기사가 서로 다른 매체 2곳 이상(밈·신조어는 7일 이내), 모든 출처가 14일 이내여야 해요. 못 맞추는 소재는 올리지 않고, 기준을 못 넘는 옛 카드는 앱의 최근 목록에서 빠져요. `validate` 가 강제해요.
- 다루는 분야 8개(앱에 보이는 순서): 경제, 세계, 연예, 스포츠, IT·과학, 생활·문화, 게임, 밈·신조어 (신문·포털의 큰 분류를 참고했어요. 아래 '분야' 참고)
- 정책 카드 (2026-10-19 사용자 결정: 프로젝트가 오래 가도록 위험이 적은 주제부터 조금 여는 1단계): 국회·정부가 **이미 내린 결정·시행 사실**(의결·공포·발표·시행)만 `cat: 정책` 카드로 다뤄요. 하루 2개까지, 경제 · IT·과학 · 생활·문화 · 세계 분야에만 두고, 아침 알림의 대표 소식에서는 빠져요(개수에는 들어가요). 아직 정해지지 않은 일, 여야·정당·정치인, 찬반 공방, 선거·수사·재판 소식은 그대로 다루지 않아요. 검사는 글에 '국회'가 있는데 cat 이 `정책`이 아닌 카드, 정책 카드에 `날치기·폭거·꼼수·졸속·막말·망언·내로남불·정쟁·정치 공세`가 있는 카드, 정책 카드가 하루 3개 이상인 날을 막아요. `의원·정당·여당·야당·탄핵·선거` 같은 금지어는 그대로라서 이런 말이 든 제목의 기사는 출처로 못 써요. 큰 사건·사고·재난의 종료된 공식 사실은 아직 열지 않았어요(앱이 자리 잡은 뒤에 다시 정해요).
- 다루지 않는 것: 정당·정치인 공방과 선거, 범죄·사건사고·재난·사망 소식, 전쟁·테러·북한 군사 소식, 재판 중인 개인, 실명 의혹·확인되지 않은 의혹. (2026-10-19 부터 '시위·집회·파업'과 시위 기사에 으레 나오는 '경찰'·'체포', 해외 정상을 가리키는 '대통령'은 금지어에서 뺐어요. 사실만 전하는 조건이고, 검사는 자극적인 표현 `충격·경악·발칵·폭로·멘붕·아수라장` 과 투자 권유로 읽힐 표현 `수혜주·관련주·테마주·목표주가·목표가·투자의견·추천주·종목 추천·매수 추천·매도 추천·매수 의견` 을 카드 글에서 막아요.)
- `node scripts/content.mjs validate` 로 규칙을 검사해요. 어기면 사이트와 앱이 올라가지 않아요.

### 이슈 이어보기 (`firstDate`·`updates`, 0.4.3)
- 같은 이슈를 새 사실로 다시 올리면(같은 id, 더 늦은 `date`) `node scripts/content.mjs merge` 가 사전의 예전 카드에서 처음 보도일(`firstDate`)과 날짜별 한 줄 기록(`updates: [{date, line}]`, 오래된 것부터, 마지막은 지금 카드)을 이어 붙여 `today.json`·`terms.json` 에 함께 적어요. 두 필드는 직접 쓰지 않아요.
- 앱은 기록이 있는 카드에 'N일째' 배지를, 해설 화면에 '이슈 흐름'을 보여줘요. 검사는 날짜 순서·첫/마지막 날짜·금지어를 봐요(기록은 8개까지).
- 2026-10-21 에 저장소 기록(git)에서 문장이 실제로 바뀐 10개 이슈의 흐름을 되살려 넣었어요. 같은 문장으로 날짜만 바뀐 기록은 새 사실이 아니라서 넣지 않았어요.

### 분야 (내 분야 고르기)

- 사용자는 처음 실행할 때 관심 분야를 고르고(여러 개), 오늘 화면에는 고른 분야마다 한 묶음씩 나와요. 한 묶음은 **보여줄 기간(위 규칙. 모든 분야면 3일) 안의 해설을 최신 순으로** 보여줘요(가장 최근 것은 큰 카드, 나머지는 날짜가 붙은 작은 카드. 한 묶음에 20개를 넘으면 '이슈 더 보기' 버튼으로 20개씩 이어서 펼쳐요). 선택은 그 기기 안에만 저장돼요(`localStorage` 의 `wt.cats`). 오늘 화면 위쪽 '바꾸기'나 알림 탭의 '분야 바꾸기'로 언제든 바꿀 수 있어요. 오늘 해설이 아직 없는 새벽에도 어제·그저께 해설이 보여서 비어 보이지 않아요. 분야 순서는 `categories.json` 의 순서를 따라요(이미 분야를 고른 사람에게도 바로 적용돼요).
- 분야 목록(id·이름·설명·아이콘 이름·색)은 `site/data/categories.json` **하나만** 기준이에요. 앱 화면과 `scripts/content.mjs` 검사가 같은 파일을 읽어요. 카드의 `group` 은 여기에 있는 `id` 여야 해요 (meme · ent · sports · game · tech · econ · life · world).
- 분야를 더하려면 `categories.json` 에 항목을 넣고, 새 아이콘이면 `site/js/app.js` 의 `ICONS` 에 같은 이름의 그림을 더해요. (이름이 없으면 기본 그림이 나와요.)
- **분야 구성을 크게 바꿀 때**(분야를 합치거나 나눌 때)는 `categories.json` 맨 위의 `revision` 을 1 올리고, 새로 생긴 분야에는 `since`(그때의 revision), 옛 분야를 대신하게 된 분야에는 `replaces`(옛 id 목록)를 적어요. 옛 id 를 쓰는 카드(`terms.json`·`today.json` 의 `group`)는 새 id 로 옮겨요. 앱은 `revision` 이 바뀐 걸 처음 보면 기기에 저장된 선택(`wt.cats`)을 `replaces` 에 따라 새 분야로 옮기고, '분야가 새로 바뀌었어요' 화면을 한 번 보여줘서 다시 확인하고 저장하게 해요(새 분야에는 '새 분야' 표시가 붙어요). 2026-10-18 에 7개 → 8개로 바꿨어요(`revision` 2: 드라마·영화·웹툰 → 연예, 소비·먹거리 → 생활·문화, 경제·세계 신설). 2026-10-19 아침에 `revision` 3 으로 '화제 이슈'(issue) 분야를 만들고 게임을 IT·게임·과학으로 합쳤다가, 같은 날 '분야를 더하는 게 아니라 앱 전체 컨셉을 화제 이슈 중심으로 바꾸는 것'이라는 요청에 맞춰 `revision` 4 에서 issue 분야를 없애고 게임 분야를 되살렸어요(`game` 의 `since: 4`).
- 하루 카드는 7~14개(목표 9~11개), 서로 다른 분야 5곳 이상, 한 분야 최대 4개예요 (`validate` 가 강제해요). 분야마다 하루 1~2개가 목표예요. 분야마다 최근 3일 해설이 2개 이상 있으면 (모든 분야를 고른 사람도) 목록이 비지 않아요. 2개 미만인 분야는 `validate` 가 알려주지만, 숫자를 채우려고 오래된 기사로 만든 해설을 올리지는 않아요(목록이 잠시 짧은 편이 나아요).
- `site/data/recent.json`(최근 3일 해설 전부)과 `site/data/archive.json`(지난 이슈 보관함)은 사전(`terms.json`)에서 **올릴 때마다 만들어지는 파일**이에요(`node scripts/content.mjs recent`, `pages.yml`·`android.yml` 이 실행). 저장소에는 올리지 않아요(`.gitignore`). 둘 다 출처 신선도 기준(`freshnessProblems`: 출처가 너무 오래됐거나 같은 날 기사를 낸 매체가 한 곳뿐인 해설은 제외)을 통과한 해설만 담고, 사전에는 그런 해설도 그대로 남아요.
  - `recent.json`: 오늘 기준 2일 전까지(최근 3일) 해설. 앱을 켤 때마다 받는 작은 파일이에요.
  - `archive.json`: 오늘까지의 모든 해설(분야마다 가장 최근 `ARCHIVE_MAX_PER_GROUP`=300개, 약 1년치). 앱은 **3일보다 긴 기간을 보여줘야 할 때만**(분야를 6개 이하로 골랐거나, 글자로 검색하거나, 검색의 분야 칩 하나를 누르거나, 오늘 화면에서 분야 이름을 눌러 분야 전체 보기를 열었을 때) 받아 가요. 모든 분야를 고른 사람은 이 파일을 받지 않아요. 못 받으면 최근 3일만 보여주고 안내를 달아요.
  - 앱은 오늘 해설(`today.json`)과 이 파일들을 합쳐 첫 화면과 검색 화면을 만들어요. 앱 화면(`site/js/app.js` 의 `FEED_DAYS`·`windowDays`)과 검사 도구(`scripts/content.mjs` 의 `RECENT_DAYS`)의 3일은 서로 같아야 해요. `terms.json`(사전)은 계속 쌓이는 전체 보관함이고, 앱은 목록에 없는 해설을 링크로 열 때만 받아와요.
  - 영상 자동 찾기(`find-videos`)는 최근 3일 카드만 새로 검색해요. 3일이 지나 `archive.json` 으로 넘어간 카드는 기록(`.cache/video-picks.json`, 14일)에 영상이 남아 있는 동안만 계속 붙여요(새로 검색하지 않아요). 그래서 14일이 넘은 지난 이슈에는 자동으로 찾은 영상이 없을 수 있어요.
- 후보 카드를 미리 검사하려면 `node scripts/content.mjs check <파일.json>`, 그날 신선도 규칙을 만족하는 지난 화제를 사전에만 더하려면 `node scripts/content.mjs add <파일.json>` 을 써요(자세한 규칙은 `ops/daily-job.md`).

### 아침 알림 (푸시)

- 알림을 켜면 앱이 **고른 분야**(`cat_meme`, `cat_sports` …)와 **받는 시각**(`h7`·`h8`·`h9`)을 FCM 주제로 구독해요. 끄면 구독을 모두 풀고 이 기기의 알림 등록도 지워요(`deleteToken`). 알림을 켜기 전에는 앱이 기기 등록을 요청하지 않아요(매니페스트의 `firebase_messaging_auto_init_enabled=false`. 한 번 켠 뒤에는 플러그인의 `getToken()` 이 자동 등록을 다시 켜서, 끈 뒤에도 Google 서비스가 등록 값을 다시 만들 수 있어요. 주제 구독이 없으니 알림은 오지 않아요). 앱 쪽 코드는 `site/js/app.js` 의 `syncPush()`·`wantedTopics()` 예요.
- 보내는 쪽은 `scripts/push.mjs`(`push.yml`)예요. **시각마다 알림은 1개**예요(분야별로 나누지 않아요). 오늘 해설이 있으면 그 시각을 고른 기기(주제 `h8` 등)에 한 번 보내요. 제목은 '오늘 화제 이슈 N개', 내용은 서로 다른 분야의 대표 이슈 2개와 나머지 개수예요(예: `아이브 룩스 캔 킬, 준PO 2차전 KIA 2연승 외 5개 · 왜 화제인지 30초로 알아봐요`). 대표 소식은 `today.json` 카드 순서(화제성 순)에서 서로 다른 분야의 앞쪽 2개예요. 오늘 해설이 아직 안 올라왔으면 최대 25분 기다리고, 그래도 없으면 보내지 않아요(지난 해설로 '새 해설' 알림을 보내지 않아요). 알림을 누르면 앱 첫 화면이 열려요. 앱은 분야 주제(`cat_*`)도 계속 구독하지만 지금은 알림에 쓰지 않아요(2026-10-17 에 분야별 알림 → 한 개로 바꿨어요).
- **켜지는 조건**: GitHub Secrets 에 Firebase 설정이 있어야 해요. 없으면 앱은 지금처럼 기기 안 알림(매일 같은 글)만 쓰고, `push.yml` 은 아무것도 보내지 않고 끝나요.
  - `GOOGLE_SERVICES_JSON`: Firebase 콘솔에서 안드로이드 앱(패키지 이름 `issue.why`)을 등록하고 받은 `google-services.json` 의 내용 전체. 앱을 만들 때(`android.yml` → `app/scripts/prepare-fcm.mjs`) 써요. 패키지 이름이 다르면 빌드가 이유를 알려 주며 멈춰요.
  - `FCM_SERVICE_ACCOUNT_JSON`: Firebase 프로젝트 설정 → 서비스 계정 → '새 비공개 키 생성'으로 받은 JSON 의 내용 전체. 알림을 보낼 때(`push.yml`) 써요. **비밀 키예요.** 채팅·이슈·저장소에 올리지 말고 Secrets 에만 넣어요.
- 직접 해 보기: Actions 탭 → '아침 알림 보내기' → Run workflow. 처음에는 '보내지 않고 내용만 보기'를 `true` 로 두고 로그에서 보낼 내용을 확인해요.
- 시험 보내기(저장소 안에서): `ops/push-now.json` 을 만들거나 바꾼 커밋을 main 에 올리면 `push.yml` 이 그 파일대로 보내요. 예: `{"hours": [8], "dry_run": false}` → 8시를 고른 기기에 진짜로 보내요. `dry_run` 을 `false` 로 분명히 적지 않으면 보내지 않고 내용만 보여줘요. `"validate_only": true` 를 더하면 FCM 에 '검사만' 부탁해서 기기에는 가지 않고 키·프로젝트 설정이 맞는지만 확인돼요. `"use_latest": true` 를 더하면 오늘 해설이 아직 없는 자정~아침에도 저장소에 올라와 있는 가장 최근 해설로 시험해요(예약 실행에서는 쓸 수 없어요). 같은 내용으로 다시 보내려면 `"nonce"` 같은 아무 값이나 바꿔서 올려요. 결과는 Actions 실행 화면의 '알림'에 나와요. 파일을 지우는 커밋은 아무것도 보내지 않아요.
- 개인정보: 알림을 켜면 Google(Firebase Cloud Messaging)이 기기의 알림 등록 값·설치 ID·IP 등을 처리해요. 운영자는 이 값을 받지 않아요. 개인정보처리방침 6번에 적어 두었어요. 구글 플레이 '데이터 보안' 양식에는 '기기 또는 기타 ID'(앱 기능 목적, 알림을 켠 경우에만)를 적어야 해요. 양식을 쓸 때 구글 안내를 다시 확인해요.

### 사진·영상 (`media`)

- 해설 화면 위쪽에 영상 미리보기가 나오고, 영상이 없는 해설에는 이모지로 그린 '장면 그림'(`scene`, 2~4칸)이나 분야별 아이콘 그림 카드가 나와요. 예시(`example`)가 "A: …\nB: …" 모양이면 A·B 말풍선으로 보여요. 해설 맨 아래 '더 찾아보기'에는 유튜브·이미지 검색을 새 창으로 여는 버튼이 있어요(바깥 서비스의 검색 결과로 가는 링크일 뿐이고, 거기 뜨는 영상·이미지를 앱이 싣거나 고르지 않아요).
- **기사 사진·짤(밈 이미지)·커뮤니티·SNS 캡처는 쓰지 않아요.** 저작권이 올린 사람이나 매체에 있고, 출처를 적는 것(저작권법 제37조)은 쓸 때 지킬 의무일 뿐 허락을 대신하지 않아서예요. 위키미디어 등 자유 이용 사진도 라이선스를 기계로 확인할 수 없어서 넣지 않아요. (운영자는 법률 전문가가 아니에요. 넓게 공개하기 전에 한국저작권위원회 상담이나 변호사 확인을 받는 걸 권해요.)
- `scene` 은 선택 항목이고 검사(`validate`)가 모양을 확인해요: 2~4칸, 칸마다 이모지 1개 또는 영문·숫자 1~3자 글자 칩, 이모지 1개 이상. 앱에서도 같은 규칙으로 한 번 더 걸러서, 어긋나면 아이콘 그림 카드로 보여줘요. 이미지 파일이나 주소는 데이터에 넣지 않아요.
- 영상(`media`)은 **누가 올렸는지가 정해진 유튜브 영상**만 허용해요(사용자 요청: 가능한 모든 해설에 영상). 형식은 `"media": [{"type":"video","provider":"youtube","id":"<11글자>","kind":"official 또는 news","channel":"<유튜브의 채널 이름>","title":"<유튜브의 영상 제목>"}]` 이고, 영상은 카드당 1개예요(영상을 소개한 출처 기사가 있으면 `from` 에 그 기사 주소를 더할 수 있어요).
  - `official`: 소식의 당사자나 권리를 가진 곳(가수·소속사, 기업·브랜드, 구단·리그, 게임사, 영화 제작·배급사, 방송 프로그램)이 운영하는 채널의 영상. `news`: `scripts/content.mjs` 의 `NEWS_CHANNELS` 에 있는 방송·언론사 채널의 뉴스 영상. 개인·팬 채널, 리액션·모음·재업로드, 자극적인 제목(충격·경악·논란 …)의 영상은 검사(`validate`)가 막아요.
  - 영상 번호와 채널은 갱신 담당이 유튜브 페이지를 직접 열어 확인한 것만 넣어요(`ops/daily-job.md` 3-1). 확실하지 않으면 `media` 를 빼요 — 그러면 그림 카드가 나와요.
  - 사이트를 올릴 때(`pages.yml`) `node scripts/content.mjs verify-media --prune` 이 유튜브(oEmbed)에 물어 **없어졌거나 다른 곳에서 재생이 막혔거나 채널이 적어 둔 것과 다른 영상을 올릴 파일에서만 빼요**(저장소 원본과 해설 글은 그대로예요). 확인용 영상조차 열리지 않으면 아무것도 빼지 않고 건너뛰어요. 결과는 Actions 실행 화면의 '영상 확인' 줄 메모에 나와요.
  - 예전 형식(`channel` 없이 `from` 만 있는 영상 — 출처로 단 기사 페이지에 실린 영상)도 `VIDEO_FROM_HOSTS` 의 매체에 한해 그대로 받아요.
- **많이 본 관련 영상 (`clips`, 밈·신조어 카드만)**: 밈·유행어는 뉴스·공식 영상이 거의 없는데 유튜브에는 그 말을 다룬 영상이 많아서(사용자 요청: 'L을 가져가'), 그 말로 유튜브를 검색해 고른 영상을 카드당 1~2개 붙일 수 있어요. 형식은 `"clips": [{"type":"video","provider":"youtube","id":"<11글자>","channel":"<채널 이름>","title":"<영상 제목>","views":<조회수>}]` 이고 `media` 와 따로예요(그래서 이 기능을 모르는 옛 앱은 그냥 무시해요).
  - 올린 곳이 일반 채널이어도 받는 대신 검사(`validate`)가 거르고, 갱신 담당이 직접 판단하는 기준(아이가 주인공인 영상·욕설·재업로드·모음 제외)이 더해져요: ① 조회수 10만 이상(영상 페이지에서 읽은 값) ② 제목에 카드 키워드가 그대로 들어 있음 ③ 제목에 반응·모음·자극적인 말, 금지어, 초등·어린이 같은 아이 관련 단서가 없음 ④ 카드당 2개 이하·중복 없음. 사이트를 올릴 때 `verify-media` 가 `media` 와 똑같이 없어졌거나 재생이 막혔거나 채널이 다른 영상을 올릴 파일에서 빼요.
  - 앱은 `media` 가 없으면 첫 영상을 해설 위쪽에 보여주고, 나머지는 '예시' 아래 '많이 본 관련 영상' 칸에 보여줘요. 영상마다 '유튜브 영상 · 채널 · 조회수 ○○만 회 이상'(조회수는 앞 두 자리만 남기고 내려서 실제보다 크지 않게 보여줘요)과 '유튜브에 올라온 영상이에요. 내용은 왜이슈?와 관계없어요'가 함께 나와요. 영상은 출처(`sources`)가 아니라서 영상 속 내용을 카드 글에 쓰지 않아요. 규칙은 `ops/daily-job.md` 3-2.
- **영상 자동 찾기 (`find-videos`)**: 사이트를 올릴 때(`pages.yml`) 영상이 없는 카드(앱 최근 3일 목록 기준)에 이번 소식을 다룬 영상을 유튜브 검색(YouTube Data API v3)으로 찾아 **올리는 사이트에만** 붙여요(저장소의 해설 글은 그대로예요). 키는 GitHub Secrets 의 `YOUTUBE_API_KEY` 이고, 없으면 이 단계는 건너뛰어요(사용자 요청, 2026-10-18: 유튜브에는 영상이 많은데 해설에는 왜 없냐는 질문에서 시작).
  - 뉴스·행사 카드: `NEWS_CHANNELS` 채널이 카드 날짜 앞 7일~뒤 3일 안에 올린 영상 중, 제목에 키워드의 가장 구체적인 말(행사·사람 이름)이 들어 있고 지난 연도가 적혀 있지 않은 1개를 `media`(news)로 붙여요. 유튜브 검색에는 같은 행사·경매의 지난해 영상이 섞여 나오기 때문이에요. 공식 채널(`official`) 영상은 자동으로 찾지 않아요(갱신 담당이 `ops/daily-job.md` 3-1 로 찾아요).
  - 밈·신조어 카드: 조회수 10만 이상이고 제목에 키워드가 그대로 든 영상을 조회수 순으로 2개까지 `clips` 로 붙여요. 키워드가 3글자 미만이면 다른 뜻의 영상이 섞일 수 있어서 자동으로 찾지 않아요.
  - 공통: 공개·재생 허용·생중계 아님·연령 제한 없음·아이용 표시 없음·한국에서 재생 가능·길이 제한(뉴스 15분, 밈 20분)·금지어와 자극적인 제목 없음을 확인하고, 붙이기 전에 `validate` 와 같은 규칙(`validateMedia`·`validateClips`)으로 한 번 더 검사해요. 이어서 `verify-media` 가 재생 여부와 채널을 확인해요.
  - 구글이 2026년 6월부터 검색(`search.list`)을 **하루 100번까지만 무료**로 줘요(다른 호출은 하루 10,000 단위, 영상 세부 정보 `videos.list` 는 1 단위). 그래서 영상이 없는 카드만, 한 번에 12번까지(`FIND_VIDEOS_MAX_SEARCHES`) 찾고, 못 찾은 카드는 6시간이 지나야 다시 찾아요. 결과는 `.cache/video-picks.json`(저장소에는 안 올라가요)에 적고 GitHub Actions 캐시로 이어 써요. 유튜브 API 이용약관(받아 둔 정보는 30일 안에 새로 받기)을 지키려고 기록은 14일까지만 써요.
  - 결과는 Actions 실행 화면의 '영상 자동 찾기 결과' 줄 메모에 나오고, 못 찾은 카드는 '영상 자동 찾기 요약' 메모에 이유(어떤 조건에서 떨어졌는지, 허용 목록에 없어서 떨어진 채널, 가까웠던 후보)가 나와요. 못 찾은 카드를 6시간을 기다리지 않고 바로 다시 찾고 싶으면 Actions → '웹 사이트 올리기' → Run workflow 에서 '영상을 못 찾았던 카드도 … 바로 다시 찾아요'를 켜요(`--retry`, 검색 한도를 써요). 이상한 영상이 붙으면 `scripts/content.mjs` 의 `VIDEO_BLOCK_IDS`(영상 번호)·`VIDEO_BLOCK_CHANNELS`(채널 이름)에 적어서 자동으로 안 붙게 해요. 시험할 때는 `YT_API_URL`·`FV_NOW` 환경변수로 가짜 서버와 시각을 가리켜요.
- 영상은 웹·앱 모두 그 자리에서 재생해요. 유튜브는 플레이어를 넣은 쪽이 누구인지 Referer 로 알려주길 요구하고 앱이면 앱 ID 여야 해서, `app/capacitor.config.json` 의 `server.hostname` 을 앱 ID 와 같게 두었어요(앱 화면 주소가 `https://<앱 ID>/` 가 돼요). **패키지 이름(appId)을 바꾸면 hostname 도 같이 바꿔요.** 빌드(`scripts/ci-apk-check.sh`)가 이 둘이 같은지 확인해요.
- 앱 안에서 재생이 막히면(유튜브가 오류 2·5·153 을 알려줄 때) 그 기기는 기억해 두었다가 다음부터 곧바로 유튜브 앱·브라우저로 열어요. 앱 화면은 전체 화면 전환을 지원하지 않아서 전체 화면 버튼은 숨겨요. 그 자리 재생을 끄려면 `site/js/config.js` 의 `media.inlineInApp` 을 `false` 로 바꿔요.
