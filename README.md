# 왜뜨지? (why-trending)

요즘 뜨는 밈·신조어가 **왜 뜨는지**를 출처와 함께 30초로 설명해 주는 앱이에요. 안드로이드 앱과 웹 화면이 같은 코드를 써요.

> 해설은 AI가 여러 출처를 확인해 정리한 요약이에요. 틀릴 수 있어서 모든 해설에 출처 링크를 달고, 앱 안에 '내용이 이상해요' 신고 버튼을 두었어요.

## 폴더

| 폴더 | 내용 |
| --- | --- |
| `site/` | 화면(HTML·CSS·JS)과 매일 바뀌는 해설 데이터(`site/data/`). GitHub Pages로 올라가요. |
| `app/` | 안드로이드 앱 껍데기(Capacitor) 설정. 빌드할 때 `site/`를 복사해 넣어요. |
| `scripts/` | 해설 데이터 검사·합치기 도구(`content.mjs`), 아침 알림 보내기(`push.mjs`), 아이콘 생성기 등 |
| `.github/workflows/` | 자동 빌드(`android.yml`), 사이트 배포(`pages.yml`), 아침 알림 보내기(`push.yml`) |
| `ops/` | 매일 해설을 갱신하는 담당이 읽는 지침(`daily-job.md`, `fallback-runner.md`). 사이트·앱에는 올라가지 않아요. |

## 해설 데이터 규칙

- 모든 카드는 **서로 다른 매체 2곳 이상**의 출처가 있어야 해요.
- **오늘 뜨는 것을 오늘 기사로**: 카드 날짜 기준으로 가장 최근 출처가 1일 이내(밈·신조어는 3일), 3일 이내 기사가 서로 다른 매체 2곳 이상(밈·신조어는 7일 이내), 모든 출처가 14일 이내여야 해요. 못 맞추는 소재는 올리지 않고, 기준을 못 넘는 옛 카드는 앱의 최근 목록에서 빠져요. `validate` 가 강제해요.
- 다루는 분야 7개: 밈·신조어, 연예·음악, 드라마·영화·웹툰, 스포츠, 게임, 소비·먹거리, IT·테크 (아래 '분야' 참고)
- 다루지 않는 것: 정치, 사건사고, 재판 중인 개인, 실명 의혹, 사망 소식
- `node scripts/content.mjs validate` 로 규칙을 검사해요. 어기면 사이트와 앱이 올라가지 않아요.

### 분야 (내 분야 고르기)

- 사용자는 처음 실행할 때 관심 분야를 고르고(여러 개), 오늘 화면에는 고른 분야마다 한 묶음씩 나와요. 한 묶음은 **오늘 + 최근 2주(14일)의 해설을 최신 순으로 최대 7개**예요(가장 최근 것은 큰 카드, 나머지는 날짜가 붙은 작은 카드). 선택은 그 기기 안에만 저장돼요(`localStorage` 의 `wt.cats`). 오늘 화면 위쪽 '바꾸기'나 알림 탭의 '분야 바꾸기'로 언제든 바꿀 수 있어요. 오늘 해설이 없는 날에도 지난 해설이 그대로 보여서, 분야를 골라도 비어 보이지 않아요.
- 분야 목록(id·이름·설명·아이콘 이름·색)은 `site/data/categories.json` **하나만** 기준이에요. 앱 화면과 `scripts/content.mjs` 검사가 같은 파일을 읽어요. 카드의 `group` 은 여기에 있는 `id` 여야 해요 (meme · ent · screen · sports · game · shop · tech).
- 분야를 더하려면 `categories.json` 에 항목을 넣고, 새 아이콘이면 `site/js/app.js` 의 `ICONS` 에 같은 이름의 그림을 더해요. (이름이 없으면 기본 그림이 나와요.)
- 하루 카드는 7~14개(목표 9~11개), 서로 다른 분야 5곳 이상, 한 분야 최대 4개예요 (`validate` 가 강제해요). 분야마다 하루 1~2개가 목표예요. 분야마다 최근 14일 해설이 5개 이상 있으면 앱에서 5~7개가 보여요. 5개 미만인 분야는 `validate` 가 알려주지만, 숫자를 채우려고 오래된 기사로 만든 해설을 올리지는 않아요(목록이 잠시 짧은 편이 나아요).
- `site/data/recent.json`(최근 14일 해설, 분야마다 최대 7개)은 사전(`terms.json`)에서 **올릴 때마다 만들어지는 파일**이에요(`node scripts/content.mjs recent`, `pages.yml`·`android.yml` 이 실행). 저장소에는 올리지 않아요(`.gitignore`). 앱은 오늘 해설(`today.json`)과 이 파일을 합쳐 분야별 목록을 만들어요.
- 후보 카드를 미리 검사하려면 `node scripts/content.mjs check <파일.json>`, 그날 신선도 규칙을 만족하는 지난 화제를 사전에만 더하려면 `node scripts/content.mjs add <파일.json>` 을 써요(자세한 규칙은 `ops/daily-job.md`).

### 아침 알림 (푸시)

- 알림을 켜면 앱이 **고른 분야**(`cat_meme`, `cat_sports` …)와 **받는 시각**(`h7`·`h8`·`h9`)을 FCM 주제로 구독해요. 끄면 구독을 모두 풀고 이 기기의 알림 등록도 지워요(`deleteToken`). 알림을 켜기 전에는 앱이 기기 등록을 요청하지 않아요(매니페스트의 `firebase_messaging_auto_init_enabled=false`. 한 번 켠 뒤에는 플러그인의 `getToken()` 이 자동 등록을 다시 켜서, 끈 뒤에도 Google 서비스가 등록 값을 다시 만들 수 있어요. 주제 구독이 없으니 알림은 오지 않아요). 앱 쪽 코드는 `site/js/app.js` 의 `syncPush()`·`wantedTopics()` 예요.
- 보내는 쪽은 `scripts/push.mjs`(`push.yml`)예요. **시각마다 알림은 1개**예요(분야별로 나누지 않아요). 오늘 해설이 있으면 그 시각을 고른 기기(주제 `h8` 등)에 한 번 보내요. 제목은 '오늘 뜨는 소식 N개', 내용은 서로 다른 분야의 대표 소식 2개와 나머지 개수예요(예: `GS25 맛집 김밥, 준플레이오프 1차전 외 6개 · 왜 뜨는지 30초로 알아봐요`). 대표 소식은 `today.json` 카드 순서(화제성 순)에서 서로 다른 분야의 앞쪽 2개예요. 오늘 해설이 아직 안 올라왔으면 최대 25분 기다리고, 그래도 없으면 보내지 않아요(지난 해설로 '새 해설' 알림을 보내지 않아요). 알림을 누르면 앱 첫 화면이 열려요. 앱은 분야 주제(`cat_*`)도 계속 구독하지만 지금은 알림에 쓰지 않아요(2026-10-17 에 분야별 알림 → 한 개로 바꿨어요).
- **켜지는 조건**: GitHub Secrets 에 Firebase 설정이 있어야 해요. 없으면 앱은 지금처럼 기기 안 알림(매일 같은 글)만 쓰고, `push.yml` 은 아무것도 보내지 않고 끝나요.
  - `GOOGLE_SERVICES_JSON`: Firebase 콘솔에서 안드로이드 앱(패키지 이름 `io.github.dodasifamily.issuewhy`)을 등록하고 받은 `google-services.json` 의 내용 전체. 앱을 만들 때(`android.yml` → `app/scripts/prepare-fcm.mjs`) 써요. 패키지 이름이 다르면 빌드가 이유를 알려 주며 멈춰요.
  - `FCM_SERVICE_ACCOUNT_JSON`: Firebase 프로젝트 설정 → 서비스 계정 → '새 비공개 키 생성'으로 받은 JSON 의 내용 전체. 알림을 보낼 때(`push.yml`) 써요. **비밀 키예요.** 채팅·이슈·저장소에 올리지 말고 Secrets 에만 넣어요.
- 직접 해 보기: Actions 탭 → '아침 알림 보내기' → Run workflow. 처음에는 '보내지 않고 내용만 보기'를 `true` 로 두고 로그에서 보낼 내용을 확인해요.
- 시험 보내기(저장소 안에서): `ops/push-now.json` 을 만들거나 바꾼 커밋을 main 에 올리면 `push.yml` 이 그 파일대로 보내요. 예: `{"hours": [8], "dry_run": false}` → 8시를 고른 기기에 진짜로 보내요. `dry_run` 을 `false` 로 분명히 적지 않으면 보내지 않고 내용만 보여줘요. `"validate_only": true` 를 더하면 FCM 에 '검사만' 부탁해서 기기에는 가지 않고 키·프로젝트 설정이 맞는지만 확인돼요. `"use_latest": true` 를 더하면 오늘 해설이 아직 없는 자정~아침에도 저장소에 올라와 있는 가장 최근 해설로 시험해요(예약 실행에서는 쓸 수 없어요). 같은 내용으로 다시 보내려면 `"nonce"` 같은 아무 값이나 바꿔서 올려요. 결과는 Actions 실행 화면의 '알림'에 나와요. 파일을 지우는 커밋은 아무것도 보내지 않아요.
- 개인정보: 알림을 켜면 Google(Firebase Cloud Messaging)이 기기의 알림 등록 값·설치 ID·IP 등을 처리해요. 운영자는 이 값을 받지 않아요. 개인정보처리방침 6번에 적어 두었어요. 구글 플레이 '데이터 보안' 양식에는 '기기 또는 기타 ID'(앱 기능 목적, 알림을 켠 경우에만)를 적어야 해요. 양식을 쓸 때 구글 안내를 다시 확인해요.

### 사진·영상 (`media`)

- 해설 화면 위쪽에 영상 미리보기가 나오고, 영상이 없는 해설에는 이모지로 그린 '장면 그림'(`scene`, 2~4칸)이나 분야별 아이콘 그림 카드가 나와요. 예시(`example`)가 "A: …\nB: …" 모양이면 A·B 말풍선으로 보여요. 해설 맨 아래 '더 찾아보기'에는 유튜브·이미지 검색을 새 창으로 여는 버튼이 있어요(바깥 서비스의 검색 결과로 가는 링크일 뿐이고, 거기 뜨는 영상·이미지를 앱이 싣거나 고르지 않아요).
- **기사 사진·짤(밈 이미지)·커뮤니티·SNS 캡처는 쓰지 않아요.** 저작권이 올린 사람이나 매체에 있고, 출처를 적는 것(저작권법 제37조)은 쓸 때 지킬 의무일 뿐 허락을 대신하지 않아서예요. 위키미디어 등 자유 이용 사진도 라이선스를 기계로 확인할 수 없어서 넣지 않아요. (운영자는 법률 전문가가 아니에요. 넓게 공개하기 전에 한국저작권위원회 상담이나 변호사 확인을 받는 걸 권해요.)
- `scene` 은 선택 항목이고 검사(`validate`)가 모양을 확인해요: 2~4칸, 칸마다 이모지 1개 또는 영문·숫자 1~3자 글자 칩, 이모지 1개 이상. 앱에서도 같은 규칙으로 한 번 더 걸러서, 어긋나면 아이콘 그림 카드로 보여줘요. 이미지 파일이나 주소는 데이터에 넣지 않아요.
- 영상은 **누가 올렸는지가 정해진 유튜브 영상**만 허용해요(사용자 요청: 가능한 모든 해설에 영상). 형식은 `"media": [{"type":"video","provider":"youtube","id":"<11글자>","kind":"official 또는 news","channel":"<유튜브의 채널 이름>","title":"<유튜브의 영상 제목>"}]` 이고, 영상은 카드당 1개예요(영상을 소개한 출처 기사가 있으면 `from` 에 그 기사 주소를 더할 수 있어요).
  - `official`: 소식의 당사자나 권리를 가진 곳(가수·소속사, 기업·브랜드, 구단·리그, 게임사, 영화 제작·배급사, 방송 프로그램)이 운영하는 채널의 영상. `news`: `scripts/content.mjs` 의 `NEWS_CHANNELS` 에 있는 방송·언론사 채널의 뉴스 영상. 개인·팬 채널, 리액션·모음·재업로드, 자극적인 제목(충격·경악·논란 …)의 영상은 검사(`validate`)가 막아요.
  - 영상 번호와 채널은 갱신 담당이 유튜브 페이지를 직접 열어 확인한 것만 넣어요(`ops/daily-job.md` 3-1). 확실하지 않으면 `media` 를 빼요 — 그러면 그림 카드가 나와요.
  - 사이트를 올릴 때(`pages.yml`) `node scripts/content.mjs verify-media --prune` 이 유튜브(oEmbed)에 물어 **없어졌거나 다른 곳에서 재생이 막혔거나 채널이 적어 둔 것과 다른 영상을 올릴 파일에서만 빼요**(저장소 원본과 해설 글은 그대로예요). 확인용 영상조차 열리지 않으면 아무것도 빼지 않고 건너뛰어요. 결과는 Actions 실행 화면의 '영상 확인' 줄 메모에 나와요.
  - 예전 형식(`channel` 없이 `from` 만 있는 영상 — 출처로 단 기사 페이지에 실린 영상)도 `VIDEO_FROM_HOSTS` 의 매체에 한해 그대로 받아요.
- 영상은 웹·앱 모두 그 자리에서 재생해요. 유튜브는 플레이어를 넣은 쪽이 누구인지 Referer 로 알려주길 요구하고 앱이면 앱 ID 여야 해서, `app/capacitor.config.json` 의 `server.hostname` 을 앱 ID 와 같게 두었어요(앱 화면 주소가 `https://<앱 ID>/` 가 돼요). **패키지 이름(appId)을 바꾸면 hostname 도 같이 바꿔요.** 빌드(`scripts/ci-apk-check.sh`)가 이 둘이 같은지 확인해요.
- 앱 안에서 재생이 막히면(유튜브가 오류 2·5·153 을 알려줄 때) 그 기기는 기억해 두었다가 다음부터 곧바로 유튜브 앱·브라우저로 열어요. 앱 화면은 전체 화면 전환을 지원하지 않아서 전체 화면 버튼은 숨겨요. 그 자리 재생을 끄려면 `site/js/config.js` 의 `media.inlineInApp` 을 `false` 로 바꿔요.
